Problem
During backtest replay, position sizing calls getBars() -> ensureRange(..., 'ohlcv-1d') on every EXECUTE message. The prefetch() call before each message only warms 1-minute quote ticks, not daily bars. On the first encounter of each symbol at a new date window, ensureRange() finds no coverage and makes a 2-3s Databento network call. The cache accumulates across runs but only covers windows that were previously requested — if the backtest date range was recently extended, or if a symbol appears on a date past the cached range end, it's a cold miss every time.

Decision
Insert a Phase 1.5 between intent extraction (Phase 1) and message replay (Phase 2) in runner.ts. After intents are extracted, collect all unique symbols from tradableMessages, then call priceProvider.preSeedDailyBars() to warm ohlcv-1d bars for the full backtest date range before replay starts. The lookback is barsBack=15 trading days before startDate (ATR(14) + 1 for true range calculation, mirroring atr.ts:54). preSeedDailyBars() is a thin public method on DatabentoMarketDataProvider wrapping the private ensureRange() — necessary because ensureRange is private and runner.ts cannot call it directly.

Key Files
src/backtest/runner.ts — Phase 1.5 block inserted between Phase 1 complete log and stats tracking (~15 lines). Uses getPreviousTradingDayKey to walk back exactly 15 trading days from startDate, then dayBoundsUTC for proper ET day boundary alignment.
src/backtest/market-data.ts — preSeedDailyBars(symbols, start, end) added as public method. Filters out OCC option symbols (options don't use daily bars for ATR sizing) then loops ensureRange per equity symbol with 'ohlcv-1d' schema override.

Watch Out
isRangeCovered() requires a stored interval to FULLY contain [startMs, endMs] — partial coverage is a miss. This is why caches accumulate incrementally: each new date window extends coverage by exactly one day at a time, causing perpetual misses until pre-seeded. The pre-seed eliminates this by covering the entire backtest range in one fetch per symbol. Do not attempt to inline the preSeedDailyBars loop directly in runner.ts by calling ensureRange — it is private. Do not derive barsBack from trader configs at runtime; the value (15) is a known constant from atr.ts and fetching all trader configs just to read it is over-engineering with a backwards-compat ?? 14 fallback that violates codebase rules.
