## Problem

Going live without disk safety: log files grew unbounded (day-roll only, no size cap),
a 54MB profiling artifact was committed once and could recur, and the backend had no
startup guard against low disk.

## Decision

Three targeted fixes:

1. .gitignore: added profiling-data.json, *.cpuprofile, *.heapprofile, *.heapsnapshot,
   isolate-*.log — these are generated by Node.js --prof, clinic.js, and 0x and can be
   50MB+. The 54MB file appeared in commit 1817466 and was manually removed in 296fbfe
   but was never gitignored, so it would recur after any profiling session.

2. log-rotation.ts: added 100MB intra-day size cap. Previous behaviour: one file per
   UTC day, no upper bound. New behaviour: also rolls when bytesWritten + chunk > 100MB,
   naming the overflow file with a timestamp key (YYYY-MM-DDTHH-MM-SS) to stay sortable
   and avoid collisions. Existing file size is read at stream-open so the counter is
   accurate even when the process restarts mid-day with an existing file.

3. disk-check.ts + src/index.ts: checkDiskSpace() uses fs.statfs() (Node 18.15+, safe on
   v22) to read bavail*bsize for the filesystem containing PROJECT_ROOT. Throws if free
   space < MIN_FREE_DISK_GB (default 5, env-overridable). Called as the very first async
   step inside main() before the PID lock — intentionally before the lock so a disk-full
   machine doesn't acquire the lock and block any future retry.

## Key Files

- .gitignore (profiling block)
- src/lib/log-rotation.ts (size cap logic, tsKey(), existingSize())
- src/lib/disk-check.ts (new)
- src/index.ts (checkDiskSpace() call)

## Watch Out

- Java sidecar already has logback with 50MB/file, 14-day, 500MB-total caps — no change needed.
- pruneOldLogs() in scripts/dev-up.ts runs on orchestrator startup only (not continuously).
  For the live case, npm run up invokes it at launch which is sufficient.
- No external log shipping configured (no Sentry, Logtail, Datadog). Logs are local only.
  If the machine dies hard, recent logs go with it.
- MIN_FREE_DISK_GB env var overrides the 5GB default — set lower only in CI/test environments.
